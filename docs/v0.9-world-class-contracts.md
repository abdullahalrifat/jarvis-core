# v0.9 world-class contract design

Status: design target / not part of Core 0.8.0

Audit date: 2026-08-25

This document defines the portable contracts Core should add for the next
hardening line. Jarvis and AI Stack Server own the actual process, filesystem,
network, database and UI enforcement.

The purpose is to prevent the local and durable products from inventing
incompatible semantics for streaming, budgets, side effects, proofs and handoff.

## Design principles

1. Core describes portable state and deterministic decisions; it does not run
   tools or providers.
2. Contracts are explicit about identity and idempotency.
3. Absence of evidence is not success.
4. Repository/model/connector content cannot broaden permissions.
5. Provider-specific adapters may expose richer capabilities without leaking
   provider-specific payloads into the portable run contract.
6. Every new contract needs malformed-input and backwards-compatibility tests.

## 1. Inference identity

Model name alone is insufficient for routing/fallback identity.

Proposed type:

```python
@dataclass(frozen=True)
class InferenceRouteIdentity:
    provider: str
    model: str
    endpoint: str
    credential_id: str | None = None
```

`credential_id` is a non-secret stable identifier/digest for configuration
identity; Core never receives the credential value.

Consumers use this to:

- deduplicate fallback routes;
- decide whether an existing provider client is reusable;
- record route identity in proof/calibration;
- prevent accidental key reuse across endpoints/providers.

Proposed event kinds:

```text

```

Portable envelope:

```python
@dataclass(frozen=True)
class AgentEvent:
    version: int
    event_id: str
    run_id: str
    sequence: int
    kind: str
    timestamp: float
    payload: Mapping[str, Any]
    attempt: int | None = None
    lease_id: str | None = None
    idempotency_key: str | None = None
```

Core validates ordering/shape/terminal transitions. Jarvis may emit events to
memory/JSONL/TUI; Server persists the same semantics durably.

## 3. Steer/interrupt commands

A client command targets an existing run, not a new task:

```python
@dataclass(frozen=True)
class RunCommand:
    run_id: str
    command_id: str
    kind: Literal["steer", "interrupt", "cancel", "approve", "deny"]
    text: str | None = None
    action_id: str | None = None
    expected_sequence: int | None = None
    lease_id: str | None = None
```

Deterministic rules:

- repeated `command_id` is idempotent;
- stale lease/action approval is rejected;
- completed mutations are not replayed after steering;
- interruption creates a resumable checkpoint when possible.

## 4. Typed side-effect capabilities

Move beyond a single mutation boolean:

```python
class SideEffectClass(str, Enum):
    READ_ONLY = "read_only"
    FILESYSTEM_WRITE = "filesystem_write"
    PROCESS_EXECUTION = "process_execution"
    PROCESS_STDIN = "process_stdin"
    NETWORK_READ = "network_read"
    EXTERNAL_SIDE_EFFECT = "external_side_effect"
    SECRET_ACCESS = "secret_access"
```

A tool proposal declares its side-effect class plus capability string. Core can
then compute deterministic allow/ask/deny from trusted policy inputs without
knowing how the tool is implemented.

Examples:

- `read_file` => READ_ONLY
- `apply_patch` => FILESYSTEM_WRITE
- `run_command` => PROCESS_EXECUTION
- `browser_open` => NETWORK_READ
- `browser_click` / `browser_type` => EXTERNAL_SIDE_EFFECT
- MCP tool => explicit declared class from administrator policy

Plan mode denies every non-read-only class.

## 5. Evidence coverage

Replace confidence based on absence of failure with explicit states:

```python
class VerificationState(str, Enum):
    NOT_RUN = "not_run"
    PASSED = "passed"
    FAILED = "failed"
    BLOCKED = "blocked"

@dataclass(frozen=True)
class VerificationEvidence:
    subject: str
    state: VerificationState
    method: str
    artifact_id: str | None = None
    exit_code: int | None = None
```

A confidence function receives evidence coverage separately from result quality.
A behavior-changing mutation with zero verification evidence must be capped below
a "verified" tier.

## 6. Hard autonomous budgets

```python
@dataclass(frozen=True)
class RunBudget:
    max_wall_seconds: float | None = None
    max_input_tokens: int | None = None
    max_output_tokens: int | None = None
    max_model_attempts: int | None = None
    max_tool_calls: int | None = None
    max_changed_files: int | None = None
    max_changed_lines: int | None = None
    max_estimated_cost: Decimal | None = None
    max_artifact_bytes: int | None = None
    allow_paid_escalation: bool = False
```

Core should provide immutable snapshots, consumption accounting and deterministic
`continue|pause|stop|escalation_forbidden` decisions. Consumers provide provider
prices/local compute weights.

## 7. Process lifecycle contract

Core should define portable process state without spawning a process:

```text
queued -> starting -> running -> exited
                    -> cancelling -> cancelled
                    -> timed_out
                    -> failed
```

Portable descriptors include process ID/handle, owner run, stdout/stderr cursors,
start time, exit code and sandbox/policy snapshot ID. Jarvis/Server implement
PTY/stdin/process-tree behavior per OS.

## 8. Exact proof identity

Durable completion should bind:

```python
@dataclass(frozen=True)
class ExecutionIdentity:
    run_id: str
    task_id: str | None
    attempt: int
    lease_id: str | None
    proof_id: str
```

A mutable `latest` pointer is only convenience UI state, never authoritative
ownership for durable completion.

## 9. Skill/plugin lock identity

Portable run metadata should capture immutable extension identity:

```python
@dataclass(frozen=True)
class ExtensionLock:
    name: str
    version: str
    digest: str
    publisher: str | None
    signature_id: str | None
    permissions: tuple[str, ...]
```

Core validates lock format/compatibility; consumers decide trust and installation.

## 10. Local/cloud handoff

Portable handoff should contain references/digests, not credentials:

```python
@dataclass(frozen=True)
class HandoffDescriptor:
    repository_url: str
    base_commit: str
    dirty_patch_artifact: str | None
    transcript_artifact: str | None
    source_proof_id: str | None
    budget_id: str
    policy_id: str
    skill_lock_id: str | None
    model_policy: str
```

Server/worker credentials are resolved at destination from trusted configuration.

## Compatibility strategy

- Event and proof envelopes carry explicit versions.
- New optional fields are additive inside a minor line.
- Breaking state/decision semantics require a coordinated release.
- Consumers advertise supported protocol/features before remote execution.
- Cross-repository tests use the released Core wheel, not an accidental checkout.

## v0.9 Core acceptance gates

1. deterministic unit/property tests for event ordering and terminal states;
2. duplicate/stale run command rejection;
3. budget boundary and overflow tests;
4. side-effect policy truth table including plan mode;
5. `NOT_RUN` evidence can never become verified confidence;
6. inference identity tests for same-name/different-endpoint routes;
7. proof identity/lease consistency checks;
8. serialization/backwards-compatibility fixtures;
9. package build/Twine/coverage plus consumer compatibility against the immutable
   release artifact.

Core should not be version-bumped merely for this design document. The package
version changes only when the contracts are implemented and validated.
